Command line

One binary, three commands

omajot is one binary. It runs the hub or the desktop daemon, or it prints a QR code.

omajot hubomajot daemonomajot qrConfig fileTools

omajot hub

Runs the hub: it stores all changes, sends them to your devices, stores attachments and serves the web app.

omajot hub [--port 8787] [--data <dir>] (--login <tailscale login> | --no-auth)
           [--web <dir>] [--bind 127.0.0.1] [--url <public url>] [--timeout-ms N]
FlagDefaultMeaning
--port8787The port on the bind address.
--data./omajot-dataThe folder for batches.jsonl (all changes) and blobs/ (attachments).
--loginnoneOnly requests with this Tailscale-User-Login header may use /api/*. tailscale serve sets the header.
--no-authoffNo login check, for local tests. The hub refuses to start with it on an address other than loopback.
--webweb/dist of the checkoutThe web app to serve.
--bind127.0.0.1The IPv4 address to listen on. Keep loopback when you use tailscale serve.
--urlfrom tailscale serve statusThe URL for phones. The hub prints it with a QR code when it starts.
--timeout-ms{{num:src/hub/hub.zig:request_timeout_ms}}The deadline for normal requests, in milliseconds. The event stream has its own deadline of {{ms:src/hub/hub.zig:sse_timeout_ms}} and ends cleanly {{ms:src/hub/hub.zig:sse_margin_ms}} before it.

Give exactly one of --login and --no-auth. Stop the hub with Ctrl+C: it finishes the open requests first.

omajot daemon

The plugin runs the daemon for you. The daemon keeps the local copy of your notes, syncs it with the hub, and handles paste. It speaks JSON lines on stdin and stdout, so you can also use it from scripts.

omajot daemon [--hub <url> | --no-hub] [--data <dir>]
FlagDefaultMeaning
--hubhub in the config fileThe hub URL. Without a hub, the daemon keeps your notes on this computer only.
--no-huboffDo not sync, also when the config file names a hub.
--datadata in the config file, else ~/.local/share/omajotThe local copy: the log of all changes, the queue of unsent changes, and attachments/.

An example session:

$ omajot daemon --no-hub --data /tmp/notes
{"ev":"sync","state":"offline","pending":0,"head":0}
{"id":1,"cmd":"create","folder":null,"text":"# Hello\nfrom a script #demo"}
{"re":1,"ok":true,"note":"n-c48c3ae4cbe96ad4-1"}
{"ev":"notes","upsert":[{"id":"n-c48c3ae4cbe96ad4-1","title":"Hello","snippet":"from a script #demo","tags":["demo"],…}]}
{"id":2,"cmd":"search","q":"script"}
{"re":2,"ok":true,"ids":["n-c48c3ae4cbe96ad4-1"]}

Each request gets one reply ("re"). Events ("ev") can come at any time.

docs/PROTOCOL.md lists all commands and events. The plugin and the web app use the same commands.

Run only one daemon for one data folder. Two daemons on the same folder can overwrite each other's files.

omajot qr

Prints a URL and its QR code in the terminal. Without a URL, it uses hub from the config file. Without a configured hub, it shows how to set one up.

omajot qr [url]
$ omajot qr https://your-mac.your-tailnet.ts.net:8443
{{qr_terminal}}

The QR code is black on white, also in a dark terminal. Phones scan it best at a normal font size.

The config file

~/.config/omajot/config.json (or $XDG_CONFIG_HOME/omajot/config.json). All fields are optional.

{
  "hub": "https://your-mac.your-tailnet.ts.net:8443",
  "data": "~/.local/share/omajot"
}

omajot uses the first value it finds:

  1. the command-line flag (--hub, --data),
  2. the plugin setting (hubUrl, dataDir), when it is not empty,
  3. the config file,
  4. the default: no hub, and ~/.local/share/omajot for the data.

tools/seed_sample.py

Puts the sample notes from examples/sample-notes/ into a new copy: 26 notes in 8 folders, with tags, checklists, tables and images. The screenshots on this site use them.

$ tools/seed_sample.py --data /tmp/omajot-demo-replica --hub http://127.0.0.1:8787
